[Upl# Nexo WS relay

Минимальный WebSocket-сервер, который нужен клиенту `nexo.html` для:

- мгновенного статуса «в сети» / «был(а)…» (часть — через сам сокет,
  плюс у вас уже отдельно работает presence через Firebase, так что
  статус будет обновляться даже если этот сервер временно недоступен);
- индикатора «печатает…»;
- мгновенной доставки сообщений, реакций, прочтения, звонков (WebRTC
  signalling) без опроса сервера раз в несколько секунд.

Он **не хранит** сообщения и не проверяет пароли — это чистый релей:
получил сообщение с полем `to`, переслал его нужному логину. История
переписки и данные пользователей у вас и так лежат в отдельном shared-
хранилище (тот же механизм, что использует `dbGet`/`dbSet` в
`nexo.html`).

## Запуск локально

```bash
cd server
npm install
npm start
```

По умолчанию слушает `ws://localhost:3080` — это как раз тот адрес,
который `nexo.html` использует по умолчанию, если открыть файл не
через `http://`/`https://` (см. `WS_URL` в коде).

## Запуск на сервере (продакшн)

1. Разместите `server.js` и `package.json` на своём сервере (VPS,
   Render, Railway, Fly.io — подойдёт любой, где можно держать
   постоянный процесс Node.js; учтите, что бессерверные площадки
   типа обычного Vercel/Netlify для долгоживущих WebSocket не
   подходят).
2. Пропишите порт через переменную окружения `PORT` (многие
   хостинги подставляют её сами).
3. Поставьте перед сервером reverse proxy с TLS (nginx / Caddy /
   встроенный TLS хостинга), чтобы адрес был `wss://ваш-домен`.
4. Откройте `nexo.html` с того же домена по `https://` — клиент
   сам подставит `wss://` на тот же host (см. `WS_URL` в коде), и
   ничего в HTML менять не нужно.
   Либо, для теста, откройте `nexo.html` с параметром
   `?ws=wss://ваш-домен` в адресной строке.

## Проверка, что сервер работает

Откройте `nexo.html` в двух разных браузерах (или обычном + приватном
окне) под двумя разными аккаунтами, добавьте друг друга в друзья и
откройте чат — статус «в сети» и «печатает…» должны появляться сразу,
